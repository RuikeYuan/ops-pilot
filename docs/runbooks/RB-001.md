# RB-001 — Synthetic invoice worker paused

Owner: Application Operations lab maintainer  
Environment: local synthetic lab only

## Trigger and investigation

- Business probe times out, with invoices queued.
- Confirm API liveness and inspect worker state and oldest pending age.
- Confirm the timeline records deliberate fault injection. In this lab that is direct evidence, not an inferred production root cause.

## Preconditions and approval

- Correct lab/environment confirmed.
- Worker state is `paused`.
- Operator explicitly approves resume. Do not apply this runbook to an unknown production incident.

## Action

Select **Approve recovery · RB-001**. This changes the in-process worker flag. The API records approval and rejects resume if the worker is already running.

## Verification

1. Run a new business probe and confirm PASS.
2. Confirm pending work drains and review completed invoice state.
3. Confirm no continuing degradation during observation.
4. Record evidence and measured UTC timestamps in the incident report.

## If verification fails

Keep the incident open. Inspect application stdout, SQLite availability, and queue state. Stop further changes and document the current state for handoff. Re-pausing can contain processing but does not undo invoices already completed; no data rollback is implemented.
